# v0.3.0 整合验证记录

日期：2026-10-16；环境：Windows x64，Python 3.11 conda，PyInstaller 6.20.0。

## 本地测试与构建

- 67 项离线测试通过，包括模型路由、独立队列、错误释放、原生回调所有权、配置持久化和两页窗口布局。
- 假后端实际进入 42 个工作线程，并观察到剩余两个请求只在该池排队；另一个池能独立完成请求。这说明本地准入与线程预算没有固定的 32/40 限制，不代表真实上游可以稳定处理 42 并发。
- 微信输入法的两个假原生请求可重叠执行，清理按 owner 隔离；一个请求成功不会清除另一个请求的清理故障状态。
- Tk 原生布局在 96/120/144/192 DPI、选中示例音频、108 个微信名额以及不同窗口尺寸下检查按钮和父容器矩形，两个页面均通过。
- Windows 免安装 ZIP 已完成构建、CRC 检查及文件清单检查，包含两份原生 agent、HTML 文档及依赖；未包含运行设置、日志和本地 video 素材。

## 打包后的 EXE

`--self-test` 通过：三种后端及模型、Frida、WebSocket、FFmpeg、Tk、示例音频、Win32 托盘与 DPAPI。

`--self-test-lifecycle` 的七项检查通过：启动和鉴权、关闭隐藏并保留服务、托盘恢复、两页布局、改密钥后重启自有服务、托盘退出并停止子进程、重新打开恢复密钥。测试使用程序注册的菜单回调，没有通过物理鼠标操作，也不提交音频。

## 真实语音请求

使用 `tests/verify_unified_live.py`，只提交仓库合成的 6.28 秒 `test.wav`。源码服务和最终 EXE 启动的服务均验证了输入法与豆包各两路同时请求。

最终 EXE 结果：

| 模型 | 请求数 | 结果 | 完成依据 | 观察到的本池峰值 |
|---|---:|---|---|---:|
| wetype-voice | 2 | HTTP 200，文字匹配合成样本 | server_end_flag | 2 |
| doubao-voice | 2 | HTTP 200，文字匹配合成样本 | final_and_session_finished | 2 |

文字比较仅忽略空白与标点，不忽略文字缺失、重复或乱序。最后一轮输入法约 2.24–2.30 秒完成，豆包约 8.12–8.19 秒完成；这些是单次环境下的数据，不是性能保证。四个请求结束后所有池的占用和排队数归零，测试服务正常退出，输入法进程仍在运行。

当前未运行微信桌面客户端，本轮没有重新验证微信原生识别，也没有验证更高上游并发、长时间压力、断网恢复或所有音频格式。既有微信清理和并发回归测试通过，不能替代真实客户端复验。
