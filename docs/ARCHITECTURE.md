# 架构和原生边界

```text
OpenAI SDK / HTTP 客户端
          |
          | multipart POST /v1/audio/transcriptions
          v
FastAPI（本机监听、输入验证、单请求准入）
          |
          v
音频解码为 16 kHz / mono / PCM16
          |
          v
Frida 元数据读取 -> 已加载 DLL 指纹核验
          |
          v
微信进程内 agent.js
  原生编码器 -> 自建 iLink 会话 -> 现有登录和网络层
          |
          v
微信语音识别服务 -> 响应回调 -> 最终 UTF-8 文本
          |
          v
取消并析构自建会话 -> 卸载 agent -> HTTP 响应
```

网络发送和析构在微信已有的有效协程上下文中执行，不能直接从 Frida 工作线程调用。这一条件来自运行时异常与反汇编的交叉验证。

`agent.js` 中的 RVA、虚表和对象布局仅对应已核验的 4.1.13.65 DLL。构造回调、原生字符串对齐分配与释放、异步响应保护和析构必须一起适配；不能只替换几个地址。

早期试验存在脚本卸载时遗留回调的问题，微信随后退出。当前实现对自建会话执行取消、析构和虚表释放，清理失败时禁用回调并暂停后续转写。这能缩小已知风险，有限的成功复验不能证明所有失败路径或长期运行都安全。

`server_response` 日志中 `seq` 是旧标签，读取的是对象 `+0x04` 的原始整数，完整业务语义未恢复；它不是公开保证的网络序号。API 只返回已验证的最终 `text`，不伪造时间戳、置信度或模型使用量。

默认不会保存上传音频和转写文本。合成测试语音、API 兼容测试与本机运行记录分开：公开仓库只保留源码和合成 fixtures，运行报告、日志、PID、环境和密钥配置均被 Git 忽略。
